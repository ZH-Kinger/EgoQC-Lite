# 跨来源普遍性实验协议

状态：预注册方案，不是已测结果。当前 434-clip 实验只证明缓存、解码和推理链路可运行，不能证明模型准确率或普遍性。

## 为什么 5,034 个 clip 仍然不够

2026-08-20 对开发机现有队列做了只读盘点：公共 EgoDex 为 2,856 个 clip / 2,856 个独立 `split_group`；三批供应商数据为 1,800 个 clip / 308 个独立组；内部 OSS 为 378 个 clip / 126 个独立组。合计 5,034 个 clip，但只有 3,290 个独立原视频组。

旧 OSS 合并队列把 126 个数据集统一写成了 `oss-unclassified`。规划器从只读 `raw_source_uri` 恢复任务族和数据集 ID，但来源所有权仍标为 `unclassified_mounted_dataset`，在完成资产归属确认前不把它伪装成供应商或内部数据。

供应商和内部数据存在同一原视频切出多个 clip 的情况。若随机按 clip 划分，训练集和测试集可能共享人物、场景、设备和视频内容，指标会虚高。因此论文样本量以 `split_group` 为独立单位，clip 数只用于计算处理量。

## 三套互不混用的样本池

1. **系统吞吐池：至少 100,000 个独立 clip。** 可无人工标签，用于测解码、缓存、规则门控、GPU/CPU 吞吐、失败恢复和成本。不能用于准确率结论。
2. **模型训练池：目标 30,000 个独立 clip。** 教师 API 和本地大模型的弱标签只能进入训练集；人工 Gold 与难例应提高占比。至少覆盖 4 类来源、8 个独立数据集和 6 种采集设备/方案。
3. **人工 Gold 池：目标 10,000 个独立 clip。** validation 2,500、同域 test 3,500、完全留源 external test 4,000。测试集不得用教师标签替代人工标签，也不得用于选阈值。

当前 Gold 不是“还差一点”，而是尚未形成：现有人工复检候选和教师预测均不能自动记为 Gold。

## 划分规则

- 同一 `split_group` 只能出现在一个 split。
- 同一参与者/session、相机、采集批次和任务模板应尽量整体留出，不能只打散 clip。
- external test 至少完整留出一个供应商或公开数据集，训练阶段不可见。
- 公共 raw video、视频+文本、部分手部状态、完整 MANO+相机四种能力形态都要报告。
- 每个错误类型同时包含正例、近似负例、干净对照和开放世界异常；稀有错误需要定向富集，不能依赖均匀随机抽样。

## 99% 目标如何佐证

“整体准确率 99%”会掩盖稀有严重错误。本项目采用 `recall @ validation-selected precision`，并要求自动决策 precision 的 95% Wilson 置信区间下界达到 0.99。若观测到零个假阳性，单个任务仍至少需要 381 次自动正判；一旦出现假阳性，所需数量更大。

所以报告必须同时给出：每任务、每来源、最差来源、采集设备、输入能力形态的指标，以及 macro/micro、置信区间、拒判覆盖曲线和错误片段。达不到统计量的类别只能报告“证据不足”，不能写成 99%。

## 当前阶段结论与下一步

- 434 条 few-B 结果改称系统 pilot，不再作为普遍性证据。
- 现有 3,290 个独立组可作为第一批候选池，但 Gold 目标仍短缺 10,000 个独立人工标签组。
- 下一轮扩样优先增加新的原视频、供应商、设备和 raw ego 数据；不再通过同视频多切 clip 制造表面样本量。
- 先建 100,000-clip 无标签吞吐池，同时从跨来源候选中分层抽取 10,000 个 Gold；其中 20% 双人标注，全部分歧仲裁。
- `/mnt/data` 与 `/mnt/workspace` 是同一 CPFS 根的两个挂载别名，不能再把路径前缀当作物理隔离。
- 原始命名空间 `/mnt/data/oss`、`/mnt/data/shutu`、`/mnt/data/egodex` 及其 `/mnt/workspace/*` 别名均禁止写入。
- 后续新派生产物统一写入 `/mnt/workspace/egoqc-derived`；代码用设备号和 inode 识别挂载别名，不能只做字符串前缀判断。

机器可读的预注册阈值位于 `config/qc_generality_protocol_v1.json`。
